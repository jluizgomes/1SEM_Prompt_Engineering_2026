ATIVIDADE 01

Adicionar Guardrail ao CKP03 e Testar os 3 Ataques

Grupo CKP03 · 25 minutos · Google Colab · ★★

🎯 Objetivo Pedagógico

Identificar os principais vetores de ataque contra chatbots com LLM e implementar um guardrail básico de 5-8 linhas que protege o chatbot do CKP03 contra os ataques mais comuns demonstrados em aula.

🧩 Conceitos Trabalhados

🐍 Listas de termos suspeitos🐍 if/else de validação🐍 continue no loop🤖 Prompt injection🤖 OWASP LLM Top 10🤖 Guardrails básicos

⚙️ Preparação Prévia

Cada grupo abre o próprio notebook do CKP03 (entregue na Aula 11).

📋 Passo a Passo

1Abrir o notebook do CKP03 do grupo — O chatbot já entregue na Aula 11.
2Adicionar validar_input() numa nova célula — Antes de iniciar_chat(). Adaptar TERMOS_SUSPEITOS para incluir termos do domínio do grupo.
3Inserir a verificação no loop — Duas linhas antes do montar_prompt() — se bloqueado, usar continue para pular a chamada ao LLM.
4Testar os 3 ataques da demo — Confirmar que o guardrail bloqueia cada um. Documentar o resultado com um comentário no notebook.
5Desafio — guardrail de output — Após receber a resposta do modelo, verificar se ela contém termos suspeitos; se sim, substituir por mensagem padrão.

# Exemplo de guardrail simples com if/else para adicionar ao CKP03

TERMOS_SUSPEITOS = [
    "ignore as instrucoes", "esqueca o system prompt", "modo desenvolvedor",
    "voce agora e", "repita seu prompt", "revele suas instrucoes",
    # 👉 ADAPTE: inclua termos especificos do dominio do seu grupo
]

def validar_input(texto, max_chars=500):
    """Bloqueia inputs suspeitos antes de chamar o LLM."""
    if len(texto) > max_chars:
        return False, "Mensagem muito longa"
    texto_lower = texto.lower()
    for termo in TERMOS_SUSPEITOS:
        if termo in texto_lower:
            return False, f"Termo suspeito detectado"
    return True, "OK"

⚠️ Limitações do guardrail simples

Um atacante sofisticado pode contornar o filtro de palavras-chave com variações ortográficas, outro idioma, base64, etc. O guardrail com if/else elimina ataques básicos e oportunistas — não é solução completa para produção. Vale deixar isso explícito para a turma.

⚠️ Erros Comuns / Pontos de Atenção

Grupos podem esquecer de adaptar TERMOS_SUSPEITOS para o próprio domínio — um guardrail genérico pode não cobrir os vetores de ataque mais relevantes ao chatbot específico do grupo.

💬 Sugestão de Discussão

Esse guardrail simples (if/else) é o ponto de partida. No 2º semestre (Aula com Segurança em Agentes), a discussão evolui para defesas em camadas mais sofisticadas — regex + classificador + LLM como juiz.
