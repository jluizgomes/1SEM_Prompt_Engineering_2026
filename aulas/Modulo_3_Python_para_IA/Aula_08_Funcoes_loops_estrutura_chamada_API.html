Glossário da Aula 08

📦
Função (def)
Bloco de código com nome próprio que executa uma tarefa específica e pode ser chamado quantas vezes for necessário.

Analogia: uma receita de bolo escrita uma vez, usada toda vez que você quiser fazer bolo. Você não reescreve a receita — só a segue.
🔌
Parâmetro
Variável que a função recebe como entrada para trabalhar. Definida no def; preenchida quando a função é chamada.

Analogia: os ingredientes da receita. A receita pede "2 ovos" — você fornece os ovos quando vai fazer o bolo.
📤
return
Instrução que encerra a função e devolve um valor ao código que a chamou. Sem return, a função executa mas não entrega nada.

Analogia: o bolo pronto que sai do forno. A receita termina e você recebe o resultado.
🔁
Loop for
Estrutura que repete um bloco de código uma vez para cada item de uma lista, sem copiar e colar a mesma chamada várias vezes.

Analogia: fazer a mesma receita 5 vezes seguidas, uma para cada convidado — mesma função, ingredientes (parâmetros) diferentes a cada rodada.
🔗 Por que este módulo existe
Nas Aulas 04–07 você escreveu o mesmo código de setup 4 vezes. Nas Aulas 09, 10 e 11 você vai precisar chamar o modelo dezenas de vezes. Encapsular em função resolve os dois problemas: menos repetição e mais fácil de mudar.

O problema que funções resolvem

Compare as duas versões abaixo. Ambas fazem a mesma coisa — testar 3 prompts:

❌ Sem função — código repetido
# Prompt 1
resp = client.chat(
  model="qwen3.6:27b",
  messages=[{"role":"user",
  "content": prompt1}]
)
print(resp["message"]["content"])

# Prompt 2 — código idêntico
resp = client.chat(
  model="qwen3.6:27b",
  messages=[{"role":"user",
  "content": prompt2}]
)
print(resp["message"]["content"])

# Prompt 3 — idem...
12 linhas por prompt. 36 linhas para 3 prompts. Se mudar o modelo, alterar em 3 lugares.
✅ Com função — chamada simples
# Define uma vez
def chamar_llm(prompt):
  # ... lógica aqui
  return resposta

# Usa quantas vezes quiser
chamar_llm(prompt1)
chamar_llm(prompt2)
chamar_llm(prompt3)

# Mudar modelo? 1 lugar só.
1 linha por chamada. Se mudar o modelo, alterar em 1 lugar. Para sempre.
🧠 O princípio do DRY — Don't Repeat Yourself
Todo código duplicado é um risco: quando você precisa mudar algo (o modelo, a temperatura, o endpoint), precisa lembrar de mudar em todos os lugares. Com uma função, você muda uma vez e todos os usos são atualizados automaticamente.

As 4 partes de uma função Python

anatomia_funcao.py
① def somar(② a, b):        # ① palavra-chave def + nome + ② parâmetros
    ③  resultado = a + b      # ③ corpo — o que a função faz
       ④ return resultado        # ④ return — o que a função devolve

# Chamando a função — fornecemos os argumentos
total = somar(3, 5)           # a=3, b=5
print(total)                    # → 8
Cada parte explicada
def somar(...):
① def + nome — declara a função. def é a palavra reservada. somar é o nome que você inventa. Os : no final são obrigatórios.
(a, b)
② parâmetros — os "ingredientes" que a função recebe. Podem ser 0, 1, 2 ou mais. Quando você chama a função, você fornece os valores reais (argumentos).
resultado = a + b
③ corpo — o bloco de código que executa quando a função é chamada. Deve estar identado (4 espaços). Pode ter quantas linhas precisar.
return resultado
④ return — devolve um valor ao chamador. Encerra a função. Sem return, a função executa mas devolve None (nada).

Parâmetro com valor padrão — a chave da nossa função

Um parâmetro pode ter um valor padrão. Se o chamador não fornecer esse parâmetro, o padrão é usado automaticamente.

parametro_padrao.py
# Parâmetro com valor padrão: system="" (string vazia por padrão)
def chamar_llm(prompt, system=""):
    # "prompt" é obrigatório — sempre precisa ser fornecido
    # "system" é opcional — se não passar, usa "" (string vazia)
    pass  # implementação virá na demo

# Chamando SEM system prompt — usa o padrão ""
chamar_llm("Qual é a capital do Brasil?")

# Chamando COM system prompt — sobrescreve o padrão
chamar_llm(
    prompt="Qual é a capital do Brasil?",
    system="Você é um professor de geografia. Responda em 1 frase."
)
💡 Por que system="" como padrão?
Na maioria dos testes rápidos, você não precisa de um system prompt. Colocar system="" como padrão torna a função flexível: funciona com ou sem persona. Você usa a persona quando precisa; ignora quando não precisa.
✅ Ordem importa
Parâmetros obrigatórios (sem padrão) SEMPRE vêm antes dos opcionais (com padrão). def f(prompt, system="") — correto. def f(system="", prompt) — Python recusará.

Cada linha da função — sem mistério

Anatomia de chamar_llm()
def chamar_llm(prompt, system="", modelo="..."):
Nome da função + 3 parâmetros. prompt obrigatório. system e modelo têm defaults — opcionais.
"""..."""
Docstring — documentação interna da função. Aparece quando você chama help(chamar_llm). Boa prática, não obrigatório.
mensagens = []
Lista vazia que vai receber as mensagens. Começamos vazia porque pode ou não ter system prompt.
if system:
if system: é verdadeiro quando system não é vazio ("" é falso em Python). Evita mandar system prompt vazio ao modelo.
mensagens.append({"role": "system"...})
.append() adiciona um item ao final da lista. Adiciona o system prompt como dicionário com chave "role".
mensagens.append({"role": "user"...})
Sempre adiciona a mensagem do usuário (o prompt). Isso acontece independentemente de ter system ou não.
resp = _client.chat(...)
A chamada real ao modelo. O underscore em _client indica que é uma variável "privada" — convenção, não obrigação.
return resp["message"]["content"]
Extrai só o texto da resposta e devolve. Quem chamou a função recebe uma string — sem precisar navegar no dicionário toda vez.

5 prompts em loop — o poder da função

Com a função pronta, testar 5 prompts é trivial. O professor executa ao vivo:

# 5 prompts para testar a função em loop
prompts_teste = [
    "O que é Python? Responda em 1 frase.",
    "Cite 3 linguagens de programação populares.",
    "Qual é a diferença entre IA e Machine Learning? Máximo 50 palavras.",
    "Escreva um comentário engraçado sobre programação.",
    "O que vou aprender neste semestre de Prompt Engineering?",
]

# Loop sobre a lista — 1 linha de código por chamada
for i, p in enumerate(prompts_teste, 1):
    print(f"\n── Prompt {i} ──────────────────")
    print(f"Pergunta: {p}")
    print(f"Resposta: {chamar_llm(p)}")

# Teste com system prompt — persona de professor
print("\n── Com persona de professor ──────")
print(chamar_llm(
    prompt="O que é recursão?",
    system="Você é um professor paciente. Use 1 analogia simples. Máx. 80 palavras."
))
🎯 O que acabou de acontecer
5 chamadas ao LLM em 3 linhas de lógica — o loop faz o trabalho. Sem a função, seriam 60+ linhas. Com a função, o código é legível: você vê exatamente o que está testando, sem ruído de infraestrutura. Esta é a diferença entre escrever código e escrever bom código.

Novo conceito Python: enumerate()

Apareceu no código da demo. Vale entender:

# Sem enumerate — você não sabe o índice
frutas = ["maçã", "banana", "laranja"]
for fruta in frutas:
    print(fruta)
# maçã / banana / laranja

# Com enumerate — você tem índice + valor
for i, fruta in enumerate(frutas, 1):
    print(f"{i}. {fruta}")
# 1. maçã / 2. banana / 3. laranja

# O "1" em enumerate(frutas, 1) é o início
# do contador — padrão é 0, usamos 1 para
# exibição mais natural
💡 Quando usar enumerate
Quando você precisa do item e da posição dele na lista ao mesmo tempo. Comum quando você quer numerar resultados ou comparar respostas em ordem.
💡 O que você já sabe vs. o que aprendeu
Já sabia: for item in lista
Hoje aprendeu: for i, item in enumerate(lista, 1)

Mesma estrutura, mais informação por iteração.

Funções de chamada à API no mercado real

LangChain
llm.invoke() — a versão industrial da nossa função
O LangChain usa exatamente o mesmo padrão: uma função que recebe um prompt e retorna texto. llm.invoke("prompt"). A diferença é que suporta mais backends, logging automático e integração com chains. O conceito é idêntico ao que você escreveu hoje.
Startups de AI
Wrapper functions como padrão de arquitetura
Toda startup que usa LLM em produção tem um arquivo llm_client.py ou ai_utils.py com uma função wrapper. É o lugar onde ficam retries, logging, tratamento de erros e configurações centrais. Você escreveu a versão simplificada desta função hoje.
Testes A/B de prompt
Loop para comparar versões
Times de Prompt Engineering usam exatamente o loop que você fez — uma lista de variantes de prompt, um for que chama a função, comparação dos outputs. É como os principais LLMs do mercado são avaliados internamente: loops de testes automatizados.

Boas práticas ao escrever funções

Não basta fazer funcionar — é importante escrever código que outros (e você no futuro) consigam entender:

✅ Nome descritivo
chamar_llm() diz o que faz.
f() ou processar() não dizem.
✅ Uma responsabilidade só
Nossa função faz uma coisa: enviar prompt → retornar texto. Não imprime, não salva arquivo, não faz parse do JSON. Quem chama ela decide o que fazer com o resultado.
✅ Docstring
A string entre """...""" logo após o def explica o que a função faz. Aparece no help() e IDEs.
✅ Parâmetros padrão sensatos
system="" e modelo="qwen3.6:27b" fazem sentido. Se mudar o modelo padrão, muda uma vez na definição.
⚠️ Armadilha clássica — função gigante
Funções que fazem 10 coisas ao mesmo tempo são difíceis de testar e difíceis de entender. Se sua função tem mais de 30 linhas, provavelmente faz coisas demais. Divida em funções menores.

Nossa chamar_llm() tem 8 linhas — deliberadamente simples.
⚠️ Não coloque a chave de API na função
A API key fica no Secrets do Colab, acessada via userdata.get(). Nunca coloque a chave como string hardcoded dentro da função ou no código. Regra da Aula 04 que segue válida.

Perguntas frequentes — Funções em Python

PerguntaResposta
"Posso chamar uma função dentro de outra função?"Sim, e é muito comum. Na Aula 10, você vai ter uma função montar_prompt() que é chamada dentro do loop que chama chamar_llm(). Funções que chamam funções é o padrão básico de decomposição de problemas.
"A função precisa ter return?"Não — se a função só faz algo (imprime, salva arquivo) sem precisar devolver um valor, pode não ter return. Mas nossa chamar_llm() precisa devolver o texto da resposta, então o return é essencial.
"O que é o _client com underscore?"Convenção do Python: o underscore no início indica que é uma variável "interna" — não precisa ser acessada diretamente de fora. Não é obrigatório, mas comunica a intenção ao leitor do código.
"Por que a variável se chama mensagens (plural)?"Porque é uma lista — pode ter 1 mensagem (só user) ou 2 (system + user). A lista messages vai crescer na Aula 09 quando adicionarmos histórico.
"Posso mudar o nome da função?"Tecnicamente sim. Mas nas próximas aulas o material vai referenciar chamar_llm() especificamente. Recomenda-se manter o nome para facilitar o acompanhamento.

O que vem na Aula 09 — histórico de conversa

⚠️ O problema que aparece
Com a função atual, o modelo não lembra do que foi dito antes. Se você perguntar "como te chamas?" e depois "o que acabei de te perguntar?", ele não vai saber.

Isso é porque cada chamada à API é independente — o modelo não tem memória entre chamadas.
💡 A solução: a lista messages
O histórico de conversa é simplesmente a lista messages crescendo. A cada turno, você adiciona a pergunta do usuário e a resposta do assistente. Na próxima chamada, você passa tudo.

É exatamente como os assistentes de IA populares funcionam por trás dos panos.

def chamar_llm(prompt, system="", modelo="qwen3.6:27b"):
    """Envia um prompt ao LLM e retorna a resposta como texto."""
    mensagens = []
