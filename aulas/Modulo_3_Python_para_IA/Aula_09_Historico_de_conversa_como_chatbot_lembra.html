Glossário da Aula 09

🫙
Stateless (sem estado)
Sistema que não guarda informação entre chamadas. Cada requisição é tratada de forma independente, sem memória do passado.

Analogia: atendente de fast food que não sabe seu pedido anterior — cada vez que você vai, começa do zero.
🧠
Stateful (com estado)
Sistema que mantém informação entre interações. O contexto acumulado influencia as respostas seguintes.

Analogia: o médico que conhece seu histórico — ele lembra do que conversaram na última consulta.
🔄
Loop while True
Loop que repete indefinidamente até encontrar um comando de parada (break). Ideal para loops de conversa onde não sabemos quantos turnos haverá.

Analogia: uma conversa — você não sabe quantas mensagens vai ter antes de encerrar.
🔗 Conexão com a Aula 08
Na Aula 08 você construiu chamar_llm(prompt, system=""). Hoje você vai modificá-la para aceitar o histórico completo — em vez de uma única mensagem, a função vai receber a lista acumulada de toda a conversa.

Como o histórico funciona — a lista que cresce a cada turno

Em vez de passar um prompt único, você passa a lista completa de mensagens anteriores:

historico = [
  {"role": "system",   "content": "..."},
  {"role": "user",     "content": "Oi!"},
  {"role": "assistant","content": "Olá!"}
]
# 3 mensagens na lista
🕐 Após o Turno 2
historico = [
  {"role": "system",   "content": "..."},
  {"role": "user",     "content": "Oi!"},
  {"role": "assistant","content": "Olá!"},
  {"role": "user",     "content": "Meu nome é Ana."},
  {"role": "assistant","content": "Olá, Ana!"}
]
# 5 mensagens na lista
🕐 Turno N — envia tudo
# Adiciona nova pergunta
historico.append({
  "role": "user",
  "content": "Qual é o meu nome?"
})
# Envia o histórico INTEIRO para a API
# → "Seu nome é Ana!" ← modelo lembrou!
💡 O segredo do "histórico"
Não existe memória no modelo — ele é sempre stateless. A "memória" é criada do lado do código: você guarda o histórico numa lista Python e reenvia tudo a cada turno. O modelo vê a conversa inteira como contexto e responde coerentemente.

O role "assistant" — a terceira peça do histórico

Nas Aulas 04–08 você usou só "user" e "system". Agora entra o terceiro role:

RoleQuem éQuando adicionar à listaExemplo de content
"system" Configuração do assistente — persona, regras, escopo Uma vez, no início, antes de qualquer turno "Você é um tutor de Python paciente. Nunca dê a resposta direta — guie o aluno."
"user" O que o usuário digitou naquele turno A cada turno, quando o usuário enviar uma mensagem "Como eu faço um loop for em Python?"
"assistant" O que o modelo respondeu naquele turno A cada turno, após receber a resposta da API "Que tal tentar: para cada item numa lista, faça algo. O que você acha que vai dentro do for?"
🎯 Por que guardar o "assistant" no histórico?
Sem as respostas anteriores do assistente, o modelo não sabe o que já disse. Você precisa incluir ambos os lados da conversa — user e assistant — para o contexto ser coerente. Se você mandar só os "user", o modelo não consegue manter a continuidade da narrativa.

O loop de conversa — o fluxo de cada turno

Todo chatbot com histórico segue exatamente este ciclo:

1
Ler o input do usuário — input("Você: "). Se o usuário digitou "sair", encerra o loop.
2
Adicionar ao histórico — historico.append({"role": "user", "content": entrada}). A mensagem do usuário entra na lista.
3
Chamar a API com o histórico — enviar a lista inteira. O modelo vê todo o contexto acumulado.
4
Receber a resposta — guardar o texto da resposta numa variável.
5
Adicionar a resposta ao histórico — historico.append({"role": "assistant", "content": resposta}). Isso é o que dá continuidade.
↺
Exibir e repetir — imprimir a resposta, voltar ao passo 1. O loop continua até o usuário digitar "sair".
⚠️ Janela de contexto — o limite invisível
O histórico cresce indefinidamente, mas os modelos têm um limite de tokens que podem processar de uma vez (janela de contexto). Para o Qwen3.6:27b, são 32k tokens. Para conversas longas, é necessário truncar o histórico — você verá isso no CKP03.

while True e break — o código novo desta aula

while True vs. for

# FOR — número fixo de iterações
for i in range(5):          # 5 vezes, sem surpresa
    print(i)

# WHILE TRUE — número desconhecido de iterações
while True:                 # roda para sempre...
    cmd = input("Digite: ")
    if cmd == "sair":
        break               # ...até o break
    print(f"Você digitou: {cmd}")

# .lower() — transforma em minúsculas
# "SAIR".lower() == "sair" → True
# Evita que "Sair" ou "SAIR" não funcionem

Por que while True para chat

💡 Número imprevisível
Você não sabe quantas mensagens o usuário vai mandar. for i in range(10) limitaria a conversa a 10 turnos. while True deixa o usuário decidir quando parar.
✅ break encerra limpo
break sai do while imediatamente. O código depois do while executa normalmente. Pode ser usado em qualquer condição: "sair", ctrl+C, número de turnos, etc.
⚠️ Sem break = loop eterno
Se esquecer o break, o programa trava. No Colab, clique no botão ⏹ (stop) para interromper. No terminal, use Ctrl+C.

A janela de contexto — o limite que o histórico enfrenta

O histórico cresce indefinidamente, mas o modelo só consegue processar um número limitado de tokens por vez:

📏
Qwen3.6:27b
32.768 tokens de contexto.
Em conversa normal (mensagens curtas), suporta cerca de 100–200 turnos antes de estourar.

Para o CKP03: não vai ser problema nas demos da aula.
📏
Claude 3.5 Sonnet
200.000 tokens de contexto.
Suficiente para conversas muito longas ou documentos inteiros.

Referência para entender por que modelos diferentes têm capacidades diferentes.
✂️
Truncar o histórico
Quando o histórico fica muito longo, estratégias comuns: manter só os últimos N turnos, resumir os turnos mais antigos, ou usar RAG.

No CKP03 você vai implementar a primeira estratégia: cortar os mais antigos.
⚠️ Erro que pode aparecer em conversas longas
context length exceeded — o histórico ficou maior do que o modelo suporta. Solução simples: historico = historico[:1] + historico[-8:] — mantém o system prompt e os últimos 4 turnos.

Histórico de conversa no mercado — como funciona na prática

Assistentes de IA populares
O front-end faz exatamente o que você fez hoje
Toda vez que você manda uma mensagem num assistente de IA popular, o front-end monta uma lista messages com todo o histórico da sessão e envia para a API. O modelo não tem memória — o provedor do serviço guarda o histórico no banco de dados e reenvia a cada turno. Você reimplementou isso em 20 linhas hoje.
Atendimento ao cliente digital
Histórico por sessão de atendimento
Chatbots de atendimento guardam o histórico da sessão atual — o usuário pode dizer "meu problema é o mesmo de antes" e o assistente sabe do que se trata. O histórico normalmente é descartado ao encerrar o atendimento (por privacidade e custo de tokens).
LangChain — ConversationChain
O histórico como objeto de primeira classe
O LangChain tem a classe ConversationBufferMemory que faz exatamente o que você implementou — guarda o histórico e o injeta automaticamente em cada chamada. É uma abstração do padrão que você aprendeu hoje.

Você vai usar exatamente este padrão
O chatbot especializado do CKP03 usa iniciar_chat() com system prompt de persona + templates de prompt da Aula 10. Você já tem a peça mais importante: o loop de conversa com histórico.

Síntese da Aula 09

✅
LLMs são stateless — cada chamada é independente. A "memória" que vemos nesses assistentes é implementada do lado do código: o histórico é acumulado e reenviado inteiro a cada turno.
✅
O histórico é uma lista de dicionários com 3 roles possíveis: "system" (uma vez, no início), "user" (cada pergunta) e "assistant" (cada resposta). Os 3 precisam estar presentes para o contexto ser coerente.
✅
while True com break é o padrão para loops de número indefinido de iterações. Perfeito para conversas onde o usuário decide quando parar.
✅
O fluxo de cada turno é sempre o mesmo: ler entrada → adicionar ao histórico (user) → chamar API com o histórico inteiro → guardar resposta → adicionar ao histórico (assistant) → exibir → repetir.
✅
O histórico tem limite — janela de contexto do modelo. Para conversas longas, é necessário truncar ou resumir os turnos mais antigos. No CKP03 você vai implementar a estratégia de truncamento simples.

Variações do histórico — o que você vai encontrar no mercado

EstratégiaComo funcionaQuando usar

O que vem na Aula 10 — templates de prompt com f-string

⚠️ O problema que aparece
No chatbot atual, o prompt do usuário entra direto no histórico — sem formatação, sem contexto adicional, sem guia de como responder.

Mas no CKP03 você vai querer que cada mensagem siga um formato específico: "O usuário perguntou sobre [tema]. Considere o contexto [X]. Responda em [formato]."
💡 A solução: montar_prompt()
Uma função que recebe variáveis e monta o prompt final com f-string:

def montar_prompt(pergunta, contexto="", formato=""):
  return f"Pergunta: {pergunta}\nContexto: {contexto}\nFormato: {formato}"

# Setup + chamar_llm() da Aula 08 (copiar célula 1 e 2)
# [professor cola o setup e a função chamar_llm aqui]

# ── LOOP DE CONVERSA COM HISTÓRICO ──────────────────────
def iniciar_chat(system=""):
    """Loop de conversa com histórico acumulado."""
    historico = []

    # Adiciona system prompt se fornecido
    if system:
        historico.append({"role": "system", "content": system})

    print("Chat iniciado. Digite 'sair' para encerrar.\n")

    while True:                          # ← loop infinito

        # Passo 1: ler o input do usuário
        entrada = input("Você: ")

        # Passo 1b: condição de saída
        if entrada.lower() == "sair":
            print("Encerrando chat. Até logo!")
            break                          # ← encerra o while

        # Passo 2: adicionar ao histórico
        historico.append({"role": "user", "content": entrada})

        # Passo 3: chamar API com o histórico inteiro
        resp = _client.chat(
            model="qwen3.6:27b",
            messages=historico           # ← lista inteira, não só a última
        )

        # Passo 4: extrair o texto
        resposta = resp["message"]["content"]

        # Passo 5: adicionar resposta ao histórico
        historico.append({"role": "assistant", "content": resposta})

        # Exibir e repetir
        print(f"Assistente: {resposta}\n")
        print(f"[histórico: {len(historico)} mensagens]\n")

# Iniciar com persona de tutor de Python
iniciar_chat(system="Você é um tutor de Python. Seja breve e didático.")

  3. Imprima o histórico — adicione print(historico) dentro do loop, logo após adicionar a resposta. Observe a lista crescer a cada turno.
  4. Desafio — limite de turnos: Modifique o loop para encerrar automaticamente após 5 turnos, mesmo que o usuário não digite "sair". Dica: use um contador turno = 0 que incrementa a cada iteração.

Lacuna 2: True
Lacuna 3: "sair" (e depois: break)
Lacuna 4: "user", entrada
Lacuna 5: "assistant", resposta
Lacuna 6: qualquer system prompt de sua escolha
