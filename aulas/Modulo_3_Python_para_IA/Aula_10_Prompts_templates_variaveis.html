Glossário da Aula 10

🧩
Template de prompt
Um prompt com "buracos" — partes fixas mais variáveis que são preenchidas dinamicamente com valores concretos antes de enviar ao modelo.

Analogia: um formulário com campos em branco. A estrutura é sempre a mesma; só os valores mudam.
🔤
f-string (Python)
String que começa com f"..." e pode embutir expressões Python entre {} diretamente no texto.

Analogia: um texto com colchetes onde você cola os valores — "Olá, {nome}!" vira "Olá, Ana!".
🏭
Fábrica de prompts
Função que recebe parâmetros e retorna um prompt completo pronto para enviar. Separação entre construir o prompt e enviá-lo.

Analogia: uma máquina de selos — você fornece o conteúdo; ela aplica o formato padrão.

Por que templates
Sem template, o mesmo prompt é reescrito levemente diferente a cada vez — variações que geram inconsistência no output. Template resolve isso.
04 / 28

O problema da inconsistência sem template

Imagine um sistema que gera e-mails automáticos. Sem template, cada call ao modelo pode ter variações sutis:

❌ Sem template — 3 versões ligeiramente diferentes do mesmo pedido
"Escreva um e-mail formal para Pedro sobre o atraso na entrega do projeto."
"Redija um e-mail profissional ao Pedro informando sobre o atraso na entrega."
"Gere um e-mail para o Pedro comunicando o problema com o prazo de entrega."
✅ Com template — sempre a mesma estrutura, só os valores mudam
f"Escreva um e-mail {tom} para {destinatario} sobre {assunto}.
Extensão máxima: {max_palavras} palavras.
Tom desejado: {tom}."
🎯 O que um template garante
1. Consistência: a estrutura do prompt é sempre a mesma — só os valores mudam.
2. Reutilização: uma mudança no template afeta todos os prompts gerados por ele.
3. Testabilidade: você pode testar o template com valores fixos antes de integrar ao sistema.
4. Separação de responsabilidades: quem define o template não precisa ser o mesmo que fornece os valores.

f-string — do básico ao template de prompt

O que você já sabia

# f-string simples com 1 variável
nome = "Ana"
print(f"Olá, {nome}!")    # → "Olá, Ana!"

# f-string em print do loop
for i, item in enumerate(lista, 1):
    print(f"{i}. {item}")

O que você aprende hoje

# f-string multiline com múltiplas variáveis
persona     = "especialista em Python"
tema        = "decorators"
publico     = "iniciantes"
max_linhas  = 3

prompt = f"""
Você é um {persona}.
Explique {tema} para {publico}.
Use no máximo {max_linhas} linhas.
"""

# → "Você é um especialista em Python.
#    Explique decorators para iniciantes.
#    Use no máximo 3 linhas."
💡 Triple-quotes + f-string = template multiline
A combinação de f"""...""" (f-string com triple-quotes) permite criar templates de prompt com múltiplas linhas e múltiplas variáveis — mantendo a estrutura visual do prompt legível no código.

Além de variáveis — expressões dentro do {}

A f-string aceita qualquer expressão Python entre as chaves — não só variáveis simples:

fstring_expressoes.py
# Variável simples
nome = "carlos"
print(f"Nome: {nome}")               # → "Nome: carlos"

# Método de string dentro do {}
print(f"Nome: {nome.title()}")        # → "Nome: Carlos"
print(f"Nome: {nome.upper()}")        # → "Nome: CARLOS"

# Operação matemática
limite = 100
print(f"Máximo: {limite * 2} palavras") # → "Máximo: 200 palavras"

# Condicional (expressão ternária)
formal = True
print(f"Tom: {'formal' if formal else 'informal'}")

# Aplicado a templates de prompt
eh_tecnico = False
publico    = "gestor"

prompt = f"""
Explique para um {publico}.
Nível técnico: {'alto' if eh_tecnico else 'baixo'}.
{'Inclua exemplos de código.' if eh_tecnico else 'Evite jargão técnico.'}
"""
✅ Expressão ternária — if em uma linha
valor_se_true if condição else valor_se_false — uma forma compacta de if/else que cabe dentro de uma f-string. Útil para adaptar o prompt baseado em flags booleanas.

Por que encapsular o template numa função

Você poderia usar o f-string direto. Mas encapsular em função tem vantagens concretas:

⚠️ f-string direta — funciona, mas...
# Espalhado pelo código — difícil de achar e mudar
prompt1 = f"E-mail formal para {dest}..."
# ... 50 linhas depois ...
prompt2 = f"E-mail formal para {dest}..."
# Qual é a versão correta?
✅ Função — template centralizado
def montar_email(dest, tom):
  return f"E-mail {tom} para {dest}..."

# Usado em qualquer lugar
montar_email("Pedro", "formal")
montar_email("Ana", "informal")
✅ Centralização
O template fica num só lugar. Para mudar a estrutura do prompt, você edita só a função — todos os usos são atualizados automaticamente.
✅ Validação
A função pode verificar se os parâmetros fazem sentido antes de montar o prompt — ex: se o tom é "formal" ou "informal", nada mais.
✅ Testabilidade
Você pode testar montar_prompt() sem chamar o LLM — imprime o prompt e verifica se está correto antes de gastar tokens.

Conceito novo: **dict — desempacotamento de dicionário

No código da demo apareceu montar_prompt(**c). O que é isso?

# ** desempacota o dict como argumentos nomeados
cenario = {
    "destinatario": "Pedro",
    "assunto": "atraso",
    "tom": "formal"
}

# Estas duas chamadas são idênticas:
montar_prompt(**cenario)

# É o mesmo que:
montar_prompt(
    destinatario="Pedro",
    assunto="atraso",
    tom="formal"
)

# Útil quando os parâmetros vêm de um dict
# (como na lista de cenários da demo)
💡 Por que usar **dict
Quando você tem uma lista de configurações num dict (como os cenários), usar ** evita repetir o nome de cada parâmetro.

Em vez de f(a=c["a"], b=c["b"], c=c["c"]), você escreve simplesmente f(**c).
⚠️ As chaves do dict devem casar com os parâmetros
Se o dict tem uma chave "destinatario", a função precisa ter um parâmetro destinatario. Nomes diferentes geram TypeError.

Visualizando o template — antes e depois de preencher

O template é a estrutura fixa. Os valores são os dados concretos. O prompt final é a combinação dos dois:

📐 Template (estrutura fixa + variáveis)
Você é um assistente de comunicação profissional.
Escreva um e-mail {tom} para {destinatario} sobre: {assunto}.
Contexto adicional: {contexto}
Limite: {max_palavras} palavras.
Inclua: assunto, saudação, corpo e despedida.
Responda em português brasileiro.
Cenário 1 — Formal
tom="formal"
destinatario="Pedro"
assunto="atraso na entrega"
→ E-mail formal para Pedro sobre atraso na entrega. Máx 80 palavras.
Cenário 2 — Informal
tom="informal"
destinatario="Ana"
assunto="reunião de sexta"
→ E-mail informal para Ana sobre reunião. Máx 80 palavras.
Cenário 3 — Reclamação
tom="reclamação"
destinatario="Suporte"
assunto="produto com defeito"
→ E-mail de reclamação para Suporte. Máx 80 palavras.
🎯 O mesmo template, 3 prompts completamente diferentes
A estrutura não mudou em nenhum dos 3. O que muda são apenas os valores nas variáveis. O modelo recebe prompts bem estruturados e consistentes — e responde de forma igualmente consistente.

Templates de prompt no mercado — onde isso é usado hoje

LangChain — PromptTemplate
A versão industrial do montar_prompt()
O LangChain tem a classe PromptTemplate e ChatPromptTemplate — exatamente a mesma ideia de template com variáveis, mas com validação automática, formatação avançada e integração com chains. A API do LangChain é quase idêntica ao que você construiu hoje.
E-commerce em escala
Geração de descrições em escala
E-commerces usam templates para gerar automaticamente descrições de milhares de produtos. O template define estrutura (nome, benefícios, público, CTA) e as variáveis são preenchidas com dados do catálogo. Mesma lógica do seu gerador de e-mails, em escala de 100k produtos.
Marketing automation
Templates de e-mail personalizados
Ferramentas de automação de marketing geram e-mails personalizados usando templates + variáveis de CRM (nome, empresa, cargo, histórico de compra). A diferença: elas usam LLM para gerar o texto do corpo, não só para substituir variáveis.
Serviços de atendimento ao cliente
Respostas personalizadas em larga escala
Sistemas de atendimento usam templates para gerar respostas contextualizadas: template recebe tipo de problema, nome do cliente, produto afetado, histórico de tickets. A resposta é consistente em estrutura mas personalizada em conteúdo.

Template + histórico — integração real

Como montar_prompt() e o histórico da Aula 09 trabalham juntos em um chatbot real:

integracao_template_historico.py
# Template para chatbot especializado em Python
def montar_prompt(pergunta, nivel="iniciante"):
    return f"""
Pergunta sobre Python ({nivel}): {pergunta}
{'Explique como se eu tivesse 10 anos.' if nivel == 'iniciante' else ''}
Use 1 exemplo de código curto. Máximo 3 linhas de explicação.
"""

# No loop de conversa — monta o prompt antes de adicionar ao histórico
historico = [{"role": "system", "content": "Você é tutor de Python."}]

while True:
    entrada = input("Você: ")
    if entrada.lower() == "sair": break

    # Usa montar_prompt() para formatar antes de enviar
    prompt_formatado = montar_prompt(entrada, nivel="iniciante")

    # Adiciona ao histórico — o prompt formatado, não a entrada bruta
    historico.append({"role": "user", "content": prompt_formatado})

    resp = _client.chat(model="qwen3.6:27b", messages=historico)
    resposta = resp["message"]["content"]
    historico.append({"role": "assistant", "content": resposta})
    print(f"Assistente: {resposta}\n")

Perguntas frequentes

PerguntaResposta
"Qual a diferença entre f-string e str.format()?"Ambas fazem substituição de variáveis em strings. f-string (Python 3.6+) é mais moderno, mais legível e mais rápido. str.format() é mais antigo mas ainda funciona. Para prompts, f-string é sempre a escolha preferida em Python 3.6+.
"O template deve ficar no mesmo arquivo do loop de conversa?"Para o CKP03, sim — tudo num só notebook é mais simples. Em projetos maiores, é comum separar em arquivos: templates.py com os prompts e chat.py com o loop. No 2º semestre com LangChain isso fica mais estruturado.
"Posso ter mais de uma função montar_prompt()?"Sim — e é o padrão em sistemas reais. Uma por domínio ou por tipo de tarefa: montar_prompt_email(), montar_prompt_codigo(), montar_prompt_resumo(). Cada uma especializada na sua tarefa.
"O que é o ** antes do dict na chamada da função?"**dict desempacota o dicionário como argumentos nomeados. É chamado de "unpacking operator". f(**{"a":1,"b":2}) é exatamente igual a f(a=1, b=2).

persona = "especialista"; tema = "Python"

Você é um {persona}.

f(**params)     # igual a f(a=1, b=2)

# Setup + chamar_llm() da Aula 08 (copiar célula 1 e 2)

# ── A FUNÇÃO montar_prompt() ─────────────────────────────
def montar_prompt(
    destinatario,
    assunto,
    tom="formal",
    max_palavras=80,
    contexto=""
):
    """Monta um prompt para geração de e-mail com parâmetros variáveis."""
    return f"""
Você é um assistente de comunicação profissional.
Escreva um e-mail {tom} para {destinatario} sobre: {assunto}.
{'Contexto adicional: ' + contexto if contexto else ''}
Limite: {max_palavras} palavras.
Inclua: assunto, saudação, corpo e despedida.
Responda em português brasileiro.
"""

# ── TESTAR COM 3 CONTEXTOS ───────────────────────────────
cenarios = [
    {"destinatario": "Pedro",  "assunto": "atraso na entrega",  "tom": "formal"},
    {"destinatario": "Ana",    "assunto": "reunião de sexta",   "tom": "informal"},
    {"destinatario": "Suporte", "assunto": "produto com defeito", "tom": "reclamação"},
]

for c in cenarios:
    # Monta o prompt com os parâmetros do cenário
    prompt = montar_prompt(**c)
    # Envia usando chamar_llm() da Aula 08
    email = chamar_llm(prompt)
    print(f"\n──── {c['tom'].upper()} → {c['destinatario']} ────")
    print(email)
