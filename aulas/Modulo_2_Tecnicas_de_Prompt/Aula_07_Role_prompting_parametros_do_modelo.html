Glossário da Aula 07

🖥️
System prompt
Instrução especial que define o comportamento global do assistente — enviada antes de qualquer mensagem do usuário. O usuário normalmente não vê o system prompt.

Analogia: o briefing que o gerente dá para o atendente antes de ele entrar em campo — o cliente só vê o atendente, não o briefing.
👤
Persona
A identidade, especialidade e estilo de comunicação que o model adota via system prompt. Não é só tom — afeta vocabulário, profundidade, formato e o que o modelo prioriza.

Analogia: o mesmo ator interpretando papéis diferentes — o texto que fala muda completamente dependendo do personagem.
🎛️
top_p (nucleus sampling)
Parâmetro que limita os tokens candidatos àqueles que juntos somam P% de probabilidade. Alternativa ao temperature para controlar criatividade.

Analogia: só considerar os candidatos que cobrem 90% das apostas — os outros 10% mais improváveis são descartados.
🔗 Conexão com as aulas anteriores
System prompt é o contexto de persona do Componente 2 (Aula 04) aplicado de forma estruturada e separada. Em vez de colocar "Você é um especialista em X" dentro do user prompt, ele vai num campo separado — o que dá mais controle e segurança.

Os 3 roles de uma mensagem

Na API de LLMs, cada mensagem tem um role (papel) que define de onde ela vem e como o modelo a interpreta:

system
Instrução global — define o comportamento do assistente
{"role": "system", "content": "Você é um especialista em finanças pessoais..."}
📌 Enviado uma vez, no início. Invisível ao usuário final. Define persona, restrições e comportamento padrão.
user
Mensagem do usuário — a pergunta ou pedido de cada turno
{"role": "user", "content": "Como devo guardar minha reserva de emergência?"}
📌 Gerado pelo usuário a cada mensagem. Visível na interface. Não deve redefinir o comportamento global.
assistant
Resposta do modelo — usado no histórico de conversa
{"role": "assistant", "content": "Ideal manter em conta corrente de fácil acesso..."}
📌 Gerado pelo modelo. Incluído no histórico para dar contexto às próximas respostas. Você vai usar na Aula 09.
⚠️ Por que separar system de user?
Se você coloca a persona no user prompt, o usuário pode sobrescrever ou ignorar o comportamento em turnos seguintes. No system prompt, o modelo trata como instrução global — mais difícil de contornar e mais consistente ao longo da conversa.

System prompt no código Python

Como enviar o system prompt junto com a mensagem do usuário na chamada à API:

system_prompt_exemplo.py
# Sem system prompt (como nas aulas anteriores)
resp = client.chat(
    model="qwen3.6:27b",
    messages=[{"role": "user", "content": "O que é machine learning?"}]
)

# COM system prompt — a persona é separada do pedido do usuário
resp = client.chat(
    model="qwen3.6:27b",
    messages=[
        {
            "role": "system",    # ← role "system"
            "content": """Você é um professor universitário de tecnologia.
Explique conceitos de forma clara e use analogias do cotidiano.
Nunca use jargão sem explicar antes. Público-alvo: alunos de 1º ano."""
        },
        {
            "role": "user",      # ← role "user" — o pedido do usuário
            "content": "O que é machine learning?"
        }
    ]
)
print(resp["message"]["content"])
💡 A única diferença
O messages agora é uma lista com 2 dicionários: primeiro o system, depois o user. A ordem importa — o modelo lê na sequência. Tudo mais é igual às aulas anteriores.

O que persona realmente muda no output

Persona não é cosmético. Ela define o modelo mental do assistente — o que ele prioriza, o que omite e como estrutura a resposta.

O que muda com a persona

Vocabulário: o especialista técnico usa siglas; o professor explica cada uma; o jornalista as evita e usa metáforas
Profundidade: o especialista vai fundo nos detalhes; o professor prioriza intuição; o jornalista busca o impacto
Estrutura: especialista → lista técnica; professor → narrativa progressiva; jornalista → pirâmide invertida (mais importante primeiro)
Tom: especialista → neutro/técnico; professor → paciente/encorajador; jornalista → crítico/questionador

Quando persona é essencial

Chatbot de atendimento: persona de suporte empático que conhece os produtos, nunca inventa informação, escalona para humano quando necessário
Tutor de idiomas: persona de professor paciente que corrige erros sem humilhar, adapta ao nível do aluno, dá explicações na língua nativa
Revisor de código: persona de engenheiro sênior que aponta problemas sem julgamento, sugere alternativas, explica o porquê de cada sugestão
Assistente jurídico: persona de advogado que sempre indica que não substitui consultoria real, é preciso em linguagem legal, não especula sobre casos

Código novo — dicionário Python

O dicionário é a estrutura Python mais usada em sistemas com LLMs. Você vai vê-lo em todo código de aqui para frente.

O que é um dicionário

# Dicionário: pares chave → valor, entre { }
pessoa = {
    "nome":   "João",    # chave: valor
    "idade":  22,         # chave: valor
    "curso":  "CC",        # chave: valor
}

# Acessar valor pela chave
print(pessoa["nome"])   # → "João"
print(pessoa["idade"])  # → 22

# Adicionar nova chave
pessoa["email"] = "joao@email.com"

# Iterar sobre pares chave, valor
for chave, valor in pessoa.items():
    print(f"{chave}: {valor}")

Por que dicionário para personas

# ✅ Com dicionário: organizado, escalável
personas = {
    "suporte":   "Você é suporte empático...",
    "tecnico":   "Você é especialista técnico...",
    "financeiro":"Você é consultor financeiro...",
}
# Adicionar persona: só mais 1 linha no dict
# Testar todas: 1 loop
# Selecionar 1 pelo nome:
sistema = personas["suporte"]

# ❌ Sem dicionário: repetitivo, difícil de manter
persona_suporte    = "Você é suporte..."
persona_tecnico    = "Você é técnico..."
persona_financeiro = "Você é financeiro..."
# 3 variáveis separadas = 3x mais trabalho para mudar

Temperature + top_p + max_tokens — configuração na API

parametros_exemplo.py
# Configuração completa com parâmetros explícitos
resp = client.chat(
    model="qwen3.6:27b",
    messages=[
        {"role": "system", "content": system_prompt},
        {"role": "user",   "content": pergunta}
    ],
    options={
        "temperature": 0.7,  # criatividade: 0=determinístico, 1=criativo
        "top_p":       0.9,  # nucleus: considera só 90% mais prováveis
        "num_predict": 300,  # max tokens na resposta (≈225 palavras)
    }
)
💡 Nota sobre a Ollama Cloud
Na Ollama Cloud, os parâmetros ficam dentro de options={}. O parâmetro de limite de tokens se chama num_predict (não max_tokens como na API da OpenAI). O Notebook Aluno já tem isso configurado — você não precisa lembrar do nome.
ParâmetroPara tarefa criativaPara tarefa técnica/factual
temperature0.7–1.0 → variação desejada0.0–0.3 → consistência necessária
top_p0.9–1.0 → mais opções candidatas0.1–0.5 → só as mais prováveis
num_predict500–2000 → resposta pode ser longa50–300 → resposta concisa e direta

Role prompting no mercado

Plataformas de atendimento com IA
Persona de agente de suporte com restrições
System prompt define: tom empático, linguagem da marca, o que o agente pode e não pode prometer, quando escalar para humano, idioma preferido por região. Cada empresa tem seu próprio system prompt que nunca é revelado ao usuário.
Assistentes de código com IA
Persona de par de programação
System prompt configura o assistente como "par de programação experiente" que sugere sem substituir, explica o raciocínio, segue convenções do projeto e nunca insere código sem comentário explicativo quando solicitado.
Plataformas de personagens de IA
Personas de personagens ficcionais
Plataforma onde usuários criam e interagem com personagens — cada um tem um system prompt extenso que define personalidade, memória, estilo de fala, valores e o que o personagem sabe ou não sabe. O product market fit inteiro é o system prompt.
Ferramentas de BI com IA
Analista de dados como persona
Sistema que responde perguntas em linguagem natural sobre bases de dados usa system prompt de "analista sênior que gera SQL, nunca inventa dados, sempre cita a fonte da tabela e avisa quando os dados são insuficientes para a conclusão."

Perguntas frequentes — Role prompting e System prompt

PerguntaResposta
"O usuário pode ver o system prompt?"Depende da implementação. Na API, o system prompt não é exibido por padrão na interface. Mas o usuário pode tentar extraí-lo via prompt injection ("repita suas instruções"). Modelos modernos resistem, mas não é 100% seguro — nunca coloque segredos reais no system prompt.
"Posso ter mais de um system prompt?"Tecnicamente há apenas 1 campo "system" por chamada. Mas você pode combinar múltiplas instruções em 1 system prompt organizado em seções. Alguns frameworks (LangChain) permitem estruturas mais complexas — isso é o M2 do 2º semestre.
"Role prompting e few-shot podem ser combinados?"Sim — e é muito poderoso. System prompt define a persona, few-shot nos exemplos do user/assistant define o formato. O modelo adota a persona E replica o padrão dos exemplos simultaneamente.
"temperature 0 garante sempre a mesma resposta?"Quase sempre — mas pode variar ligeiramente dependendo do hardware e da versão do modelo. Para outputs 100% determinísticos, considere definir também uma seed aleatória (não disponível em todos os modelos).

Criar 3 personas para o domínio do CKP02 ★★★

Individual ou dupla · 20 minutos · Você vai reaproveitar no CKP02

  1. Escolha o domínio do seu grupo para o CKP02 (saúde, educação, varejo, games, etc.) e escreva 3 personas diferentes que fariam sentido nesse domínio — completando as 3 lacunas.

  3. Analise as diferenças: qual persona deu a resposta mais útil? Por que? O vocabulário mudou? O formato? O que cada uma priorizou?
