A parte do prompt que diz o que o modelo deve fazer. O verbo da tarefa.

Analogia: comprar pão no mercado em vez de plantar trigo, moer a farinha e assar. A biblioteca já fez o trabalho duro.

Os 4 componentes — visão geral

1. Instrução
O que fazer. O verbo da tarefa. É obrigatório em todo prompt útil.
Exemplo: "Resuma", "Classifique como positivo/negativo/neutro", "Traduza para português formal"
2. Contexto
O que o modelo precisa saber para fazer bem. Background, persona, restrições, audiência.
Exemplo: "Você é um especialista em direito tributário. O usuário é um MEI sem formação contábil."
3. Input
O dado ou conteúdo a processar. O texto, trecho, pergunta ou dado sobre o qual a instrução vai agir.
Exemplo: "Texto: [cole aqui o e-mail do cliente]" ou "Pergunta do usuário: {pergunta}"
4. Formato
Como a saída deve ser. Tamanho, estrutura, tom, idioma, tópicos, JSON, lista.
Exemplo: "Responda em tópicos. Máximo 100 palavras. Tom formal. Sem markdown."
💡 Regra prática
Se o modelo faz escolhas que você não queria, é porque você não especificou esse elemento. Cada componente ausente é uma decisão que o modelo vai tomar por você.
📖 Fundamentação — As mesmas 4 peças, vindas de um guia diferente
Lanham (AI Agents in Action, Manning Publications, 2025) resume as táticas oficiais de "Write Clear Instructions" da OpenAI em seis pontos: perguntas detalhadas, adoção de personas, uso de delimitadores, especificação de passos, fornecimento de exemplos e definição do tamanho da saída. Cada uma cai dentro de um dos 4 componentes acima: pergunta detalhada e especificação de passos reforçam a Instrução; personas formam o Contexto; delimitadores organizam o Input; exemplos (few-shot, que você estuda na Aula 05) e tamanho da saída moldam o Formato. Não é coincidência as mesmas peças aparecerem em fontes independentes — o resultado de um LLM depende só do que está no prompt, então todo framework de boas práticas converge para nomear as mesmas lacunas que você precisa preencher.

Componente 1 — Instrução: o verbo da tarefa

A instrução define a ação. Verbos diferentes produzem resultados completamente diferentes para o mesmo input.

Verbos por categoria de tarefa

CategoriaVerbos úteis
TransformaçãoResuma, traduza, reescreva, simplifique, expanda, formate
AnáliseClassifique, identifique, extraia, avalie, compare, liste
GeraçãoEscreva, crie, gere, sugira, proponha, elabore
DecisãoDecida, escolha, priorize, ordene, recomende

Mesmo input, verbos diferentes

Input: "O produto chegou quebrado e o atendimento foi péssimo."
Resuma: "Cliente insatisfeito com produto e atendimento."
Classifique: "Negativo — produto + atendimento."
Reescreva: "Infelizmente o item chegou danificado e o suporte não foi satisfatório."
Extraia: "Problemas: 1) Produto defeituoso 2) Mau atendimento."
💡 Instrução precisa = menos surpresa
Quanto mais específico o verbo, menos liberdade o modelo tem — e menos surpresa você tem. "Resuma em 3 pontos" é melhor que "resuma".

Componente 2 — Contexto: o que o modelo precisa saber

O contexto inclui tudo que o modelo precisa para calibrar a resposta para a sua situação específica.

Persona / Role
Quem o modelo deve ser.

"Você é um médico clínico explicando para um paciente sem formação médica."
"Você é um engenheiro de software sênior revisando código de um júnior."

Muda vocabulário, tom e nível técnico da resposta.
Audiência
Para quem a resposta é destinada.

"O leitor é um executivo sem background técnico."
"O público é um aluno de 15 anos."

Mesmo conteúdo, nível de complexidade completamente diferente.
Restrições
O que o modelo não deve fazer.

"Não mencione concorrentes."
"Não use jargão técnico."
"Não invente informações — diga 'não sei' se não souber."

Guardrails via contexto.
Background / Situação
O que o modelo precisa saber sobre o cenário.

"A empresa é uma startup de 10 funcionários com orçamento limitado."
"O usuário já tentou reiniciar o computador 3 vezes."

Evita sugestões inadequadas para o contexto real.

Componentes 3 e 4 — Input e Formato

Componente 3 — Input: o dado

O conteúdo sobre o qual a instrução vai agir. Pode ser texto, dados, perguntas ou variáveis.

Texto direto:
"Texto: 'O produto chegou quebrado...'"
Variável (no código):
f"Texto: {texto_do_usuario}"
Múltiplos inputs:
"Nome: {nome}\nIdade: {idade}\nPergunta: {pergunta}"
💡 Separar input do resto
Colocar o input numa seção clara evita que o modelo confunda instrução com dado. Uso de rótulos ("Texto:", "Pergunta:", "Contexto:") ajuda muito.

Componente 4 — Formato: a estrutura da saída

Controla como a resposta aparece — sem isso, o modelo decide por conta própria.

ElementoExemplo de instrução
Tamanho"Máximo de 100 palavras", "3 parágrafos", "1 frase"
Estrutura"Em tópicos", "Em prosa", "Em tabela", "Em JSON"
Tom"Formal", "Informal", "Técnico", "Empático"
Idioma"Em português brasileiro", "Em inglês americano"
Marcação"Sem markdown", "Use negrito nos pontos principais"

Exemplo completo — os 4 componentes juntos

Um prompt real de um sistema de análise de feedback de clientes:

prompt_analise_feedback.txt 
# ── CONTEXTO ────────────────────────────────────────────
Você é um analista de experiência do cliente de uma empresa de e-commerce brasileira.
O feedback abaixo foi deixado por um cliente após a compra.
Não invente informações que não estão no texto.

# ── INSTRUÇÃO ────────────────────────────────────────────
Analise o sentimento do feedback e identifique os pontos de melhoria.

# ── INPUT ────────────────────────────────────────────────
Feedback: "O produto chegou no prazo, mas a embalagem estava amassada
e o manual veio em espanhol. O atendimento foi rápido quando reclamei."

# ── FORMATO ──────────────────────────────────────────────
Responda em JSON com os campos:
- sentimento_geral: "positivo", "negativo" ou "misto"
- pontos_positivos: lista de strings
- pontos_negativos: lista de strings
- prioridade_acao: "alta", "media" ou "baixa"
💡 Por que JSON no formato?
Ao especificar JSON como formato, o output pode ser lido diretamente por outro programa em Python — é o primeiro passo para automatizar análises. Na Aula 07 você vai explorar isso com mais profundidade.

O que vem na Aula 05 — Zero-shot, One-shot e Few-shot

Agora que você sabe chamar o modelo via código, vamos explorar como exemplos no prompt mudam radicalmente a qualidade da resposta.

🤔 O problema que vai aparecer
Você vai notar que mesmo com os 4 componentes, alguns prompts não conseguem fazer o modelo entender exatamente o que você quer — especialmente para tarefas incomuns ou que seguem um padrão específico seu.
💡 A solução: exemplos no prompt
Em vez de descrever o que você quer, você mostra. Um exemplo dentro do prompt vale mais do que dez linhas de instrução. Isso é Few-shot prompting — e é o que o LLM usa para se calibrar na sua tarefa.
🔮 Para a Aula 05
Traga uma tarefa que você goste de fazer — classificar mensagens, resumir notícias, gerar hashtags, o que for. Vamos usar como base para praticar Few-shot ao vivo com o código que você escreveu hoje.

"Preciso ter Python instalado no computador?"Não. O Google Colab roda Python direto no browser, nos servidores do Google. Você não instala nada localmente — tudo fica na nuvem.
"Qual a diferença entre pip install e import?"pip install baixa e instala a biblioteca (uma vez por sessão do Colab). import a carrega na memória para usar (em toda sessão nova). Instalar = comprar o livro. Importar = abrir o livro.

# VARIÁVEL — guarda um valor com um nome
modelo = "qwen3.6:27b"  # string (texto)
temperatura = 0.7         # float (número decimal)

# STRING — texto entre aspas. Triple quotes = múltiplas linhas
texto_curto = "uma linha"
texto_longo = """
primeira linha
segunda linha
"""

# DICIONÁRIO — pares chave:valor, acessados por colchetes
mensagem = {"role": "user", "content": "Olá"}
print(mensagem["role"])     # → "user"
print(mensagem["content"])  # → "Olá"

# LISTA — sequência de valores, acessada por índice [0]
mensagens = [mensagem]  # lista com 1 dicionário dentro

# CHAMADA DE FUNÇÃO/MÉTODO — nome() ou objeto.nome()
resposta = client.chat(model=modelo, messages=mensagens)

# F-STRING — string com variável dentro usando {}
print(f"Modelo usado: {modelo}")  # → "Modelo usado: qwen3.6:27b"

# PARÂMETRO NOMEADO (kwarg) — nome=valor dentro de uma chamada

    model=modelo, messages=mensagens,
    options={"num_predict": 150}  # max_tokens da Lacuna 3

🚀 Demo Prática — Mesmo pedido, 3 versões de prompt

O professor vai enviar as 3 versões abaixo ao Claude free tier ao vivo. Você anota o que muda.

❌ Versão 1 — Sem estrutura
"Fala sobre IA"
Resultado esperado: resposta genérica, muito longa ou muito curta, sem foco, inútil para qualquer propósito específico
⚠️ Versão 2 — Estrutura parcial
"Explique inteligência artificial de forma simples para um estudante universitário"
Resultado esperado: melhor que a versão 1, mas ainda vago — sem formato definido, sem foco de aplicação, sem tamanho

Resultado esperado: resposta focada, com analogia, com exemplos brasileiros, no tamanho certo — utilizável imediatamente
🎯 O que fez a diferença entre a V1 e a V3
Role definido ("professor universitário"), contexto ("1º ano, nunca programou"), estrutura de saída ("analogia + 3 exemplos"), limitação ("150 palavras"). Cada elemento removeu uma decisão que o modelo teria que tomar por conta própria — e tomaria diferente do que você queria.
