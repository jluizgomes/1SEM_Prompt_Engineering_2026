Glossário da Aula 02

Três termos novos hoje. Como sempre: definição + analogia antes de qualquer explicação técnica.

🧩
Token
Fatia de palavra — pode ser uma palavra inteira, parte de uma palavra ou até um espaço. É a unidade mínima que o modelo processa.

Analogia: como sílabas, mas não exatamente. "cachorro" pode virar ["cach", "orro"] ou ["ca", "chorro"] dependendo do tokenizador.
📋
Contexto (Context Window)
A quantidade máxima de tokens que o modelo consegue "ver" de uma vez — como a memória de curto prazo.

Analogia: imagine que você só consegue ler uma folha A4 de cada vez. O que estava na folha anterior, você não lembra mais.
🎲
Temperatura
Parâmetro que controla o quanto o modelo "arrisca" ao escolher a próxima palavra. 0 = sempre a mais provável; 1 = mais aleatoriedade.

Analogia: quanto o modelo "joga dados" ao escolher a próxima palavra.
💡 Esses 3 termos aparecem em toda API de LLM
Quando você chamar a Ollama Cloud no código Python (a partir da Aula 04), vai configurar exatamente esses três elementos: o que tokenizar, qual janela de contexto enviar, e qual temperatura usar.

O que é um Token
O modelo não lê palavras. Não lê letras. Lê tokens. Entender isso muda como você pensa em prompts — e explica por que o modelo às vezes "corta" palavras de forma estranha.
04 / 29

Token: a fatia que o modelo enxerga

Tokens não são palavras. São pedaços de texto que o vocabulário do modelo aprendeu durante o treinamento.

📌 Como funciona a tokenização
Palavras comuns em inglês viram 1 token. Palavras menos comuns, compostas ou em outros idiomas são divididas em múltiplos tokens. Espaços e pontuação também são tokens.

Exemplo — frase tokenizada (cada cor = 1 token):

Inteligência artificial está mudando o mercado de trabalho .

→ 9 tokens para 9 palavras/pontuação. Frase simples = 1 token por palavra.

Palavra técnica rara — pode virar múltiplos tokens:

pneumoultramicroscopicsilicovulcanoconiosis

→ 9 tokens para 1 palavra. Por isso palavras técnicas "custam mais".

"Olá, como vai?"5 tokensPalavras curtas e comuns = 1 token cada
"Hello, how are you?"5 tokensInglês é mais eficiente — modelos foram treinados com mais dados em inglês
1 página A4 de texto~500 tokensRegra prática: 1 token ≈ ¾ de palavra em português
Livro de 300 páginas~150.000 tokensAcima da janela de contexto da maioria dos modelos gratuitos

Por que tokens importam para Prompt Engineering

Tokens têm três implicações diretas no seu trabalho com LLMs:

💰
Custo
APIs pagas cobram por token — input e output. Um prompt verboso custa mais. Saber economizar tokens sem perder qualidade é uma habilidade real de Prompt Engineering.

APIs gratuitas também têm limite de tokens por minuto
📏
Limite de contexto
Seu prompt + histórico de conversa + resposta do modelo precisam caber na janela de contexto. Se passar, o modelo "esquece" o início da conversa.

Modelos comerciais de fronteira: 128k–1M+ tokens · Ollama Cloud (curso): 8k–32k tokens
🌍
Idioma
Português e outros idiomas não-ingleses geralmente usam mais tokens para o mesmo significado. "Hello" = 1 token. "Olá" = 1 token. Mas frases longas em PT-BR custam ~30% mais tokens que em inglês.

Impacto real no custo e no limite de contexto
🧮 Regras práticas de estimativa
• 1 token ≈ ¾ de palavra em português
• 100 tokens ≈ 75 palavras (um parágrafo curto)
• 1 página A4 ≈ 400–500 tokens
• "Seja conciso" no prompt economiza tokens e melhora a resposta ao mesmo tempo

02
Como o LLM gera texto
O modelo não "pensa" uma resposta e depois escreve. Ele prevê o próximo token, um de cada vez. Esta ideia simples explica quase tudo que os LLMs fazem — e por que às vezes falham.
07 / 29

Predição de próximo token — como o texto é gerado

Cada palavra que o modelo escreve é uma previsão probabilística do que vem a seguir dado tudo o que veio antes.

A → capital → do → Brasil → é → ? Modelo escolhe o próximo token:
Brasília (92%) São Paulo (4%) Rio (2%) uma... (2%)

O processo passo a passo

1. Você envia o prompt (tokenizado)
2. O modelo calcula probabilidades para cada possível próximo token
3. Escolhe 1 token (influenciado pela temperatura)
4. Adiciona o token ao contexto e repete do passo 2
5. Para quando gera um token de fim de texto ou atinge max_tokens

O que isso explica

Por que o modelo alucina
Ele não "sabe" a resposta — escolhe o token mais provável dado o contexto. Se não há boa evidência no treinamento, escolhe algo que "parece certo" mas não é.
Por que respostas variam
Com temperatura > 0, o modelo sorteia entre as opções mais prováveis. O mesmo prompt pode gerar respostas diferentes — é intencional.

Como o modelo aprendeu a prever

Durante o treinamento, o modelo viu bilhões de textos e aprendeu: "quando vejo X, a próxima palavra costuma ser Y".

📖 O treinamento em termos simples
Etapa 1 — Pré-treinamento: o modelo vê trilhões de tokens da internet, livros, código e artigos. Aprende padrões de linguagem puro — qual palavra tende a seguir qual, em qual contexto.

Etapa 2 — Fine-tuning com feedback humano (RLHF): humanos avaliam respostas e ensinam o modelo a ser útil, honesto e seguro. É o que transforma um "preditor de texto" num "assistente".

Resultado: o modelo tem um mapa interno de probabilidades para trilhões de sequências de texto. Não "sabe" fatos — sabe quais tokens tendem a aparecer juntos.
✅
O que o modelo "sabe"
Padrões de linguagem. Estrutura de argumentos. Como textos técnicos, criativos e formais se diferenciam. Código de programação. Muito de história, ciência e cultura geral.
❌
O que o modelo não sabe
O que aconteceu ontem. Se uma informação específica é verdadeira. O que você quer dizer quando é ambíguo. Se ele próprio está cometendo um erro de raciocínio.

O que é a janela de contexto

Tudo que o modelo processa em uma chamada — seu prompt, o histórico de conversa e a resposta — precisa caber nessa janela.

JANELA DE CONTEXTO — o que o modelo "vê"
💬 Usuário: Olá, me ajude a escrever um e-mail formal.
🤖 Modelo: Claro! Para quem é o e-mail e qual o assunto?
💬 Usuário: Para o meu chefe, sobre o atraso de um projeto.
🤖 Modelo: Aqui está o rascunho: "Prezado [Nome]..."
💬 Usuário: Pode deixar mais formal?
🤖 Modelo: ← gerando resposta com acesso a tudo acima
⚠️ Quando a janela enche — o que acontece
💬 Usuário: Quero escrever um e-mail... [início da conversa, fora da janela]
💬 Usuário: (muitas mensagens depois) Pode revisitar o e-mail original?
O modelo não consegue ver o início da conversa — ele "esqueceu". Vai responder como se não existisse.
📏 Tamanho das janelas em 2026
Modelos comerciais de fronteira: tipicamente 200k tokens (~150k palavras), alguns já ultrapassando 1M tokens · Modelos gratuitos via Ollama (usados nesta disciplina): 8k–32k tokens — menor, mas suficiente para os exercícios do curso

Por que o contexto importa para você

Na prática, o gerenciamento de contexto é um dos problemas mais comuns em sistemas com LLMs.

Problema 1: System prompt longo

❌ Ingênuo
System prompt com 10.000 tokens de instruções + 50 mensagens de histórico + pergunta longa = sem espaço para resposta
✅ Estratégico
System prompt conciso. Histórico comprimido por resumo. Contexto relevante injetado dinamicamente. Espaço para a resposta.

Problema 2: Conversa longa

❌ Sem gestão
Após 30+ mensagens, o modelo começa a "esquecer" a instrução inicial e o contexto do problema. A qualidade degrada.
✅ Com gestão
Resumir mensagens antigas periodicamente. Manter apenas as últimas N mensagens. Pinear informações críticas no system prompt.
🔮 Você vai implementar isso
No M3 desta disciplina, você vai construir um chatbot com histórico de conversa em Python e ver na prática como gerenciar o contexto. Hoje é só a intuição — o código vem depois.

Temperatura e Parâmetros
Temperatura não é calor. É a alavanca que controla o quanto o modelo "arrisca" ao escolher o próximo token. É um dos parâmetros mais importantes que você vai configurar.
13 / 29

Temperatura — a alavanca de criatividade

Lembra que o modelo calcula probabilidades para cada possível próximo token? A temperatura controla como ele usa essas probabilidades.

0.0 Determinístico
0.3 Focado
0.7 Balanceado
1.0 Criativo
2.0+ Incoerente
Como a temperatura reformata a mesma distribuição
Depois de "O jantar estava muito", o modelo já calculou um logit (pontuação bruta) para cada candidato a próximo token. A temperatura não muda esses logits — muda como eles viram probabilidade.
Arraste o controle de temperatura: perto de 0 a barra do candidato mais provável dispara sozinha; perto de 2 todas as barras se aproximam do mesmo tamanho.
TemperaturaComportamentoUse paraNão use para
0.0 Sempre escolhe o token mais provável. Resposta 100% repetível. Extração de dados, SQL, classificação, respostas com resposta certa Textos criativos — vai parecer robótico
0.1–0.4 Pouca variação. Consistente mas com leve flexibilidade. Análise técnica, documentação, sumarização Poesia, brainstorm, variação de tom
0.5–0.8 Equilíbrio entre consistência e criatividade. O padrão da maioria dos sistemas. Chatbots, assistentes, resposta geral Tarefas que exigem resposta única e correta
0.9–1.2 Alta variação. Cada resposta é diferente. Geração criativa, brainstorm, histórias Qualquer coisa que precise de precisão

Os outros parâmetros importantes

Temperatura não é o único parâmetro. Mas é o mais importante para começar. Os outros dois que você vai usar:

top_p (nucleus sampling)

Em vez de controlar a aleatoriedade diretamente, top_p define que o modelo só considera tokens que juntos somam P% de probabilidade.

Exemplo: com top_p=0.9, o modelo só considera as opções que juntas representam 90% da probabilidade — as menos prováveis são excluídas completamente.

Regra prática: use temperature OU top_p para controlar criatividade, não os dois ao mesmo tempo. A maioria das APIs usa top_p=1.0 como padrão (sem efeito).

max_tokens

Limita o tamanho máximo da resposta em tokens. O modelo para de gerar quando atinge esse limite — mesmo que a frase não esteja completa.

Por que configurar: sem limite, o modelo pode gerar respostas muito longas desnecessariamente, consumindo tokens e aumentando latência.

Regra prática: estime o tamanho da resposta esperada e defina max_tokens com folga de 20%. Para respostas curtas: 200. Para relatórios: 2000.
📋 Resumo dos 3 parâmetros que você vai usar no código
temperature → controla criatividade vs. precisão  |  max_tokens → limita o tamanho da resposta  |  top_p → geralmente deixar em 1.0 e mexer na temperature

Por que o modelo "mente" — a alucinação explicada

Agora que você entende predição de tokens, a alucinação faz sentido técnico.

🧠 Definição técnica
Alucinação é quando o modelo gera texto factualmente incorreto com a mesma confiança com que geraria texto correto. O modelo não "sabe" que está errado — ele apenas previu o próximo token mais plausível dado o contexto, e esse token não corresponde à realidade.
⚠️
Tipos comuns de alucinação
Fatos inventados: "Segundo o estudo de Silva (2022)..." — o estudo não existe.

Datas erradas: "O evento aconteceu em [data plausível mas incorreta]".

Mistura de fatos: dois fatos reais combinados de forma errada.

Código que não funciona: função que parece correta mas tem um bug sutil.
🛡️
Como reduzir alucinações
Peça fontes: "Cite apenas fatos que você tem certeza. Diga 'não sei' se não souber."

Temperature baixa: 0 ou 0.1 para tarefas factuais.

Forneça o contexto: cole o documento no prompt em vez de pedir que o modelo "lembre".

Verifique externamente: nunca confie em datas, nomes e números sem checar.
⚠️ A regra mais importante do semestre
Um LLM é uma ferramenta de geração de texto plausível — não um oráculo de fatos. Toda informação crítica gerada por IA deve ser verificada em outra fonte antes de ser usada em decisões reais.
📖 Fundamentação — Por que o modelo nunca sabe se está errado
Freed, Jacobs e Rózsa (Chatbots that Work, Manning Publications, 2025) chegam à mesma definição técnica por outro caminho: o LLM nunca verifica se sua resposta é verdadeira, apenas se ela é uma continuação estatisticamente provável do prompt recebido — é exatamente essa lacuna entre "parece plausível" e "é verdadeiro" que define a alucinação. Do lado de quem constrói produtos com LLM, os autores confirmam a mesma tática que o card ao lado já recomenda: fornecer o contexto correto dentro do prompt, em vez de deixar o modelo recorrer ao que "lembra" do treinamento, reduz diretamente a chance de alucinação — porque tira do modelo a necessidade de adivinhar.

Cenários práticos — quando tokens e contexto importam

CENÁRIO DE ALTO RISCO
Alucinação em demonstração pública tem custo real
Já aconteceu mais de uma vez: um modelo afirma, com total confiança, um fato verificável e errado durante uma demonstração ao vivo — e especialistas notam o erro em minutos. Quando o produto carrega uma marca, o custo reputacional de um fato não verificado supera de longe o tempo que levaria para checá-lo antes.
PRÁTICA DE MERCADO
Do Prompt Engineering ao Context Engineering
"Context Engineering" é o termo que descreve a prática — cada vez mais comum em sistemas de produção — de gerenciar estrategicamente o que entra na janela de contexto: o que fica fixo no system prompt, o que vem de ferramentas, o que é histórico descartável. Você volta a esse conceito, com profundidade, na Aula 04.
PADRÃO DE PRODUTO
Temperatura diferente por tipo de resposta
Sistemas de atendimento que lidam com dado factual (saldo, status, prazo) e com interação mais humana (uma reclamação, um pedido de desculpas) costumam variar a temperatura por tipo de resposta: próxima de 0 quando o dado não pode variar, mais alta quando o objetivo é soar natural.
ECONOMIA DE ESCALA
Custo de tokens em produção
Exemplo ilustrativo: uma aplicação com 100 mil usuários/dia, cada um enviando 500 tokens, gasta 50 milhões de tokens/dia só de input. Otimizar prompts para usar 30% menos tokens já representa uma economia mensal na casa das dezenas de milhares de dólares.

Perguntas frequentes — Tokens e contexto

PerguntaResposta
"O modelo lembra de conversas anteriores?" Não — por padrão. Cada chamada à API começa do zero. O histórico de conversa precisa ser enviado junto com cada nova mensagem. Você vai implementar isso na Aula 09.
"Se eu repetir a mesma pergunta, o modelo dá a mesma resposta?" Depende da temperatura. Com temperature=0: sim. Com temperature>0: provavelmente não. Isso é intencional — garante variação em respostas criativas.
"Quanto custa 1 token?" Em APIs comerciais pagas, o custo gira em frações de centavo por 1.000 tokens de input — varia por modelo e provedor. Para atividades desta disciplina, usamos Ollama Cloud (gratuito). APIs pagas entram em projetos reais de mercado.
"Por que modelos maiores são melhores?" Mais parâmetros = mais padrões de linguagem aprendidos = melhor capacidade de generalização. Mas "maior" não significa sempre "melhor para a sua tarefa" — um modelo menor e especializado pode superar um grande genérico.
"O modelo pode aprender com nossa conversa?" Não em tempo real. O modelo que você usa já foi treinado. Sua conversa não muda os pesos do modelo. (Algumas empresas usam dados de uso para retreinar periodicamente, mas isso é uma decisão de infraestrutura, não de cada conversa.)

O modelo em uma imagem — o ciclo completo

Do texto que você digita à resposta que aparece na tela:

1
Você escreve o prompt → texto em linguagem natural
2
Tokenizador converte → sequência de números inteiros (IDs de tokens)
3
Transformer processa → calcula probabilidades para o próximo token via mecanismo de atenção
4
Temperatura filtra → controla qual token é escolhido (mais ou menos determinístico)
5
Token escolhido → adicionado ao contexto, processo repete até gerar token de fim
→
Resultado: sequência de tokens convertida de volta em texto → você vê a resposta

🚀 Demo 2 — Temperature 0 vs 1 no playground

O professor vai abrir o playground de algum modelo (Claude ou OpenAI) e executar o mesmo prompt com temperaturas diferentes.

📝 Prompt que será testado 3 vezes com temperature 0
"Continue esta frase de 3 formas criativas diferentes: 'Era uma vez um programador que descobriu que sua IA havia...'"
🧊 TEMPERATURE = 0 — execute 3 vezes
O que esperar: a mesma resposta todas as vezes. O modelo sempre escolhe o token mais provável. Zero aleatoriedade = zero variação.
🔥 TEMPERATURE = 1 — execute 3 vezes
O que esperar: 3 continuações completamente diferentes. O modelo sorteia entre as opções mais prováveis. Cada execução é única.
🎯 A lição prática
Para tarefas que precisam de resposta consistente (classificar um e-mail como spam/não spam, extrair um CPF de um texto): temperature = 0.
Para tarefas que precisam de variação (gerar 3 opções de headline para um artigo): temperature = 0.8+.
